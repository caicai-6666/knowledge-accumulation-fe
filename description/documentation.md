# 文档撰写风格手册

> **适用范围：** `knowledge-accumulation-fe` 企业知识沉淀统一前端入口的开发与维护文档。
>
> **目标：** 让项目文档易于查找、易于扫描、可以追溯，并避免同一规则在多个位置产生漂移。

---

## 1. 命名与位置

### 1.1 文件命名

- Markdown 文件使用小写 kebab-case，例如 `request-flow.md`。
- 入口文件可使用约定名称，例如 `project.md` 和 `readme.md`。
- 文件名表达阅读主题，不机械复制代码文件或目录名称。
- `description/` 顶层只保留 `project.md`、`readme.md` 和 `documentation.md`，专题文档放入分类目录。
- 跨业务的前端基础能力归入 `platform/`，面向用户的业务功能归入 `features/`；当前目录与文档职责见[文档导航](readme.md)。
- 新建专题目录前，应确认其中存在多份职责相近且需要长期维护的文档。

### 1.2 按阅读目的组织

文档位置由其回答的问题决定：

| 内容类型 | 建议职责 |
| --- | --- |
| 项目级原则 | 长期稳定的范围、边界和质量标准 |
| 架构与设计 | 模块关系、流程、状态和关键取舍 |
| 功能与能力 | 用途、接口、依赖、限制和使用方法 |
| 参考契约 | 字段、类型、配置、Schema 和协议 |
| 运行维护 | 初始化、启动、部署、监控和排障 |

不要因为其他项目采用某种目录结构，就在当前项目中预建相同层级。

---

## 2. 单一权威来源

- 一项规则、契约或流程只能有一份完整主文档。
- 其他文档只保留理解当前上下文所需的最小说明，并使用相对链接指向主文档。
- 代码、类型、Schema 和配置负责执行精确约束，文档负责解释目的、边界和使用方式。
- 修改主文档时，应检查引用它的文档是否仍然准确。

> **原则：** 不通过复制内容提高“完整性”；通过清晰入口和稳定链接提高可发现性。

---

## 3. 页面结构

### 3.1 标题层级

- 每个文件只有一个一级标题。
- 主主题使用二级标题，仅在确有分支时使用三级标题。
- 不跳过标题层级，不为单个短段落创建无意义标题。
- 长文档开头应说明适用范围、目标以及与其他文档的关系。

### 3.2 留白与分段

- 标题、正文、列表、表格、引用块和代码块之间保留一个空行。
- 独立的大主题可使用 `---` 分隔，但不滥用分割线。
- 长段落按完整语义拆分；平行规则优先使用列表，需要对比时使用表格。

---

## 4. 表达约定

### 4.1 强调与引用

- 引用块用于强制要求、边界、风险和阅读提示。
- 粗体只突出短标签或关键术语，不包裹整段文字。
- 路径、命令、字段、状态值和代码标识符使用反引号。

### 4.2 示例与图表

- 代码块必须标明语言，例如 `javascript`、`json`、`yaml` 或 `text`。
- 示例保持最小，只展示解释当前规则所需的内容。
- 有明确先后顺序的内容使用编号列表；多项同维度比较使用表格。
- 复杂流程或状态关系可使用 Mermaid；图中只保留关键节点和关系，实现细节放在正文。
- 图表、示例和伪代码不得成为精确契约的第二份副本。

### 4.3 事实与判断

文档应明确区分：

- 可由代码、配置或运行结果直接确认的事实；
- 基于事实形成的设计判断；
- 尚未确认、尚未实现或仅用于讨论的内容。

待确认内容应显式标记，不使用确定语气描述猜测。

---

## 5. 专题文档内容

专题文档可根据复杂度裁剪，但通常应覆盖：

1. 用途与适用范围。
2. 与其他模块或规范的关系。
3. 核心概念、流程或对外接口。
4. 关键实现与设计决策。
5. 依赖、配置、限制和验证方式。

文档说明稳定设计，不逐行复述实现；只有当代码本身无法清晰表达原因时，才记录必要细节。

---

## 6. 链接与维护

- 使用相对 Markdown 链接，并让链接文本说明目标内容。
- 新建正式文档后，在 [`readme.md`](readme.md) 中增加入口。
- 移动、重命名或删除文档时，同步更新入站链接、导航和锚点。
- 行为、接口、配置或运行方式变化时，同步检查相关文档。
- 不保留指向不存在内容的占位链接。

---

## 7. 审查清单

提交文档前确认：

- [ ] 内容属于当前项目，并且依据可追溯。
- [ ] 未残留其他项目的名称、业务、路径、模块或工具约束。
- [ ] 文件位置、命名和标题层级清晰一致。
- [ ] 一项规则没有在多个位置重复维护。
- [ ] 事实、判断和待确认内容已经区分。
- [ ] 示例简短且不会与代码或机器契约漂移。
- [ ] 相对链接和锚点均有效。
- [ ] 文档描述与当前代码、配置和运行行为一致。

> 文档的价值不在于篇幅，而在于帮助读者快速找到可靠信息，并理解重要决策的依据。
